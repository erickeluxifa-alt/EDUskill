# 作业截止日期冲突与学业负荷平衡

## 目标
输入作业日历 JSON，识别同一班级在短窗口内的截止日期拥挤和 7 天预计学习时长超载，并给出延期候选。适用于教师布置作业前检查，也适用于教研组协同排布跨学科作业。

## 输入
可传 JSON 数组，也可传 `{ "assignments": [...] }`。每条记录至少包含：

```json
{
  "title": "函数单元作业",
  "course": "数学",
  "class_name": "高一1班",
  "due_date": "2026-08-24",
  "estimated_hours": 2
}
```

可选参数：`priority`（1-5，越高越不建议延期）、`weekly_capacity`（班级每 7 天可承受的预计小时数，默认 8）、`window_days`（密集截止窗口，默认 2）。

## 执行

```bash
python3 scripts/assignment_analyze.py assignments.json
python3 scripts/assignment_analyze.py assignments.json --json
```

## 输出
- 数据校验摘要：有效、无效记录数。
- 按班级列出的密集截止冲突和周负荷超载。
- 每个冲突最多 3 个延期候选，说明新日期、预计释放的负荷和优先级约束。
- 结论只作为排布建议，最终日期由任课教师和教研组确认。

## 规则
1. 同一班级两个作业截止日相差不超过 `window_days` 天，构成截止日期密集冲突。
2. 以每个作业截止日为中心统计前后 6 天内该班级作业预计小时数，超过 `weekly_capacity` 构成周负荷超载。
3. 建议日期只向后移动 1-7 天，并排除与其他作业形成新的密集冲突；优先选择移动后 7 天窗口负荷不超过容量的日期。
4. 不自动修改原始数据，不替教师决定教学优先级，也不等同于学生真实完成时长。

## 安全与边界
脚本只使用本地输入和 Python 标准库；用户可控文本会做 HTML 转义并限制长度，避免报告中的 HTML 注入和异常超长字段。日期必须是 `YYYY-MM-DD`，示例数据均为模拟数据。大规模数据建议按班级分批处理。
