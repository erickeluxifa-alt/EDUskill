# 学分达标预检助手 credit-progress-checker v1.0.0

> 教育产品 Skills 系列 2026-08-23 交付 · ht

## 核心场景
毕业季 / 学期末，教学秘书、教务处、班主任需要快速核查「某班学生毕业学分是否达标、还缺哪些课」。人工逐人逐课对账耗时易错，本工具一次导入培养方案 + 全班成绩单，自动输出每个学生的类别学分对账与缺课清单。

## 目标角色
- 教学秘书 / 教务处学籍管理员：批量预检、导出缺课清单用于通知学生；再经教务复核后入职教育部（学信网）数据报送。
- 班主任 / 辅导员：毕业班逐个学生摸底，一对一约谈缺课学生。
- 学生（可运行于本人成绩导出）：自查是否满足毕业学分。

## 教育行业属性
- 行业：高等教育教务管理（本科/高职通用），也可用于中职、继续教育毕业资格审查；
- 对标业务：学籍管理「毕业资格审核」环节，是学信网学历注册前置程序；
- 输入数据形态：培养方案（教务系统可导出）、成绩单（教务系统「成绩总表」导出），本工具零系统集成，数据经文件交接即可用。

## 可复用范围
- 场景可复用：毕业学分预检、学位/结业资格审查、转专业学分认定核对、双学位辅修学分达标检查；
- 模式可复用：与系列工具（schedule-conflict-detective 排课冲突、exam-blueprint 考试细目表）一致的「约束校验 + 缺口显式揭示 + 结构化导出」模式；课程匹配引擎（id/名称/别名/包含四段匹配）可抽为公共组件供其他学分相关技能复用。

## 核心增益
1. 专家经验 SOP：把教务人工核对（逐门对照必修、分池统计选修、总分校核）固化为可重复校验规则，包检 3 分钟/班；
2. 专业数据资产：培养方案 JSON（含类别学分要求、课程别名库）独立于成绩单，可沉淀为学校/院系的静态资产复用；
3. 工具能力：Markdown 报告（可截图沟通）+ CSV 缺课清单（可直接通知学生）+ JSON 结构化输出（可接其他系统）。

## 输入
- 培养方案：JSON（推荐，可携带 categories/min_credits/aliases）或 CSV（表头中文别名均支持）；
- 成绩单：CSV（首行表头）或 JSON（数组 / {"records":[...]}）；
- 字段别名支持中英文：学号/student_id、姓名/student_name、课程编号/id、课程名称/name、成绩/grade、学分/credits、类别/category；
- 成绩形态：数字（≥ 及格线通过）、等级（A-F/优/良/中/及格/不及格/Pass/Fail 等）。

## 依赖
- Python3（≥3.6）+ 标准库，零第三方依赖，离线可用。

## 使用示例
```bash
# 1) 最快上手：内置双学生示例
python3 scripts/credit_checker.py --demo

# 2) 真实文件：培养方案+全班成绩单
python3 scripts/credit_checker.py 2022级计算机培养方案.json 2022级成绩总表.csv

# 3) 只看一名学生并导出三种交付物
python3 scripts/credit_checker.py plan.json score.csv --student 2022001 \
    --out report.md --json-out result.json --csv-out missing.csv

# 4) 调整口径：及格线 58 / 最低总学分 165 / 任选按任意通过课程计
python3 scripts/credit_checker.py plan.json score.csv --pass-threshold 58 --min-credits 165 --pool-any
```

## 输出说明
- Markdown 报告：全校/全班达成人数汇总，每生一张「类别学分表（要求/已修/差额/状态）+ 未通过必修清单 + 差额说明 + 未在培养方案课程提示」；
- CSV 缺课清单：`学号,姓名,类别,课程,学分,状态,成绩,备注`，UTF-8 BOM（Excel 直开），已做公式注入防护；
- JSON：`{meta, min_credits, pass_threshold, pool_any, students[...]}`。

## 匹配与核算规则
1. 匹配优先级：课程编号 → 课程名称精确 → 别名（培养方案 aliases）→ 名称互相包含（≥3 字符）；
2. 一课多记录取最高成绩；补考/重修通过即计通过；
3. 必修逐门对照；选修/任选按学分池（仅计通过的课程，`--pool-any` 时任意通过课程均可按类别要求顺序计入）；
4. 总学分：培养方案 min_credits 或 `--min-credits` 覆盖，不足给缺口；
5. 成绩单中未在培养方案内的课程单独提示（人工核对，不计学分）。

## 限制与声明
1. 类别要求学分（categories）在 CSV 培养方案中无法表达，CSV 方案只做课程对照，不做类别学分要求（可用 JSON 或 `--min-credits` 补）；已默认声明类别若含「学分要求/required_credits」字段会优先读取；
2. 「任选/选修池」按培养方案列出的该类课程计（`--pool-any` 可放宽）；实际教务规则（如任选限通识、选修需课类比例）需按校规人工再审；
3. 单课程对应多学分周期、创新学分/证书转换等特殊学分未建模，属人工复核点；
4. 成绩文本无法识别（非数字非等级）按「未通过」并保留原文提示人工核对；
5. 本工具为预检辅助，正式毕业资格以学校教务系统/学信网平台结论为准。
