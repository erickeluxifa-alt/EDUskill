# Skill：教学进度计划生成器

## 一、核心场景

- **目标角色**：任课教师、教研组长、教学秘书（代排公共课/选修课）
- **触发时机**：
  1. 新学期开始前，把课程大纲章节按校历排成逐周教学进度表（多数高校要求开学前提交）；
  2. 学期中因节假日、调课调整进度，重新生成计划；
  3. 对年轻教师或外聘教师给出的进度草案做合规检查（学时是否与总课时一致、是否被考试周/节假日压缩）。

## 二、能力定位

把「课程大纲（章节 × 学时）」与「学期校历（教学周、考试周、节假日）」两个结构输入，
用贪心顺序分配把章节按每周课时容量拆入每个可授课周（可跨周拆分并标注「续」、可同周合并），
输出逐周教学计划表，同时自动检查三类典型问题并给出提示：

1. 章节学时合计与课程总学时偏差 >2 学时（以单元合计为准）；
2. 学时超出可授课周容量（节假日/考试周挤占后装不下）；
3. 计划提前结课（剩余周自动标为「机动/复习」）。

## 三、触发语句

- "帮我生成《数据结构》这学期的教学进度计划"
- "按校历把课程大纲排成每周教学进度表 data.json"
- "排教学进度表 examples/sample_input.json"
- 自然语言含「教学进度」「教学日历」「章节排周」「进度表」等关键词即命中

## 四、输入格式

### 方式一：JSON 文件（推荐）

```json
{
  "course": { "name": "数据结构", "code": "CS201", "total_hours": 56, "weekly_hours": 4 },
  "semester": {
    "start_date": "2026-09-07",           // 第1周周一日期
    "total_weeks": 18,                      // 学期总周数（含考试周）
    "exam_weeks": [17, 18],                 // 考试周（可写 "17,18" 或 "17-18"）
    "holidays": [
      { "weeks": [4, 5], "note": "国庆和中秋节" },       // 周次型节假日
      { "date": "2026-10-01", "days": 7, "note": "国庆" } // 日期型（自动换算周）
    ]
  },
  "units": [
    { "name": "绪论", "hours": 4 },
    { "name": "线性表", "hours": 10 }
  ]
}
```

字段支持中英别名与多种写法：

| JSON 字段 | 必填 | 别名 | 说明 |
|-----------|------|------|------|
| `course.name` | 是 | `课程名` | 课程名称（也可直接平铺在根节点） |
| `course.code` | 否 | `课程代码` | 课程代码 |
| `course.total_hours` | 是 | `hours`/`总学时` | 课程总学时 |
| `course.weekly_hours` | 是 | `weekly`/`周学时` | 每周上课学时 |
| `semester.start_date` | 是 | `起始日期` | 第 1 周周一，`YYYY-MM-DD` |
| `semester.total_weeks` | 是 | `weeks`/`教学周数` | 含考试周的总周数 |
| `semester.exam_weeks` | 否 | `exam`/`考试周` | 数组或 `"17,18"` 或 `"18-19"` |
| `semester.holidays` | 否 | `holiday`/`节假日` | 对象列表：`{week: 5}` / `{weeks:[4,5]}` / `{date,days,note}` |
| `units[].name` | 是 | `单元名`/`章` | 章节名 |
| `units[].hours` | 是 | `学时` | 章节学时（可为小数） |

### 方式二：简化 TXT（教学秘书粘贴习惯）

```
# start=2026-09-07      # 配置行：# key=value，支持 start/weeks/exam/holiday/weekly/code
# weeks=12
# exam=11,12
# holiday=4
数据结构 CS201 56 4     # 首行：课程名 [代码] 总学时 周学时
绪论 4
线性表 10                # 其余：单元名 学时
```

## 五、处理流程

1. **解析**：JSON/TXT → 统一内部结构（自动转义、HTML 安全）；
2. **校验**：学时/周次/日期合法性 → 错误直接退出码 2；
3. **周历**：按起始日期生成每周日期区间，过滤考试周、节假日周（含去重）；
4. **分配**：贪心顺序把章节填进可授课周（每周容量 = 周学时），跨周章节标注「（续）」；
5. **告警**：学时偏差、容量溢出、提前结课三类提示；
6. **输出**：同目录写入 `教学进度计划.md` / `.json` / `.csv`（UTF-8 BOM，可直接 Excel 打开）。

## 六、输出格式

- **Markdown**：标题 + 课程/学期信息 + 逐周表格（周次/日期/教学内容/备注），末尾附溢出学时与检查提示；
- **JSON**：结构化 `weeks[].blocks[]`、`overflow`、`warnings`，可供下游系统复用；
- **CSV**：`周次,起始日期,结束日期,教学内容,学时,备注`，带公式注入防护（单元格以 `=`/`+`/`-`/`@` 开头自动加 `’` 前缀）；
- **退出码**：0=无警告，1=有警告（内容仍正常生成），2=输入错误。

## 七、边界与限制

- 仅做「周粒度」排布，不细分到星期几节次（上课日信息 `teaching_days` 仅展示要求，可暂不提供）；
- 节假日按教学周粒度处理并注明「基于公历推算，未考虑法定假日调休/调班」；
- 跨周拆分的章节标注「（续）」；同一周最多合并多个小章节；
- 学时小数支持（如 1.5），计算以浮点累计，输出保留 1 位小数。
