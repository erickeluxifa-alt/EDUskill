# 学生实习分配规划器

## 一句话定位

输入「学生名单 + 志愿 + 单位容量/期次」，1 秒内输出确定性分配方案 + 需人工协调的缺口清单（含原因与处置建议）+ 单位×期次利用率统计（零依赖、离线可跑）。

## 场景与目标角色

- **场景**: 教务处 / 院系教学秘书在组织集中实习、顶岗实习、专业实习时，把学生按志愿分配到「实习单位 × 期次」，需同时满足单位容量、专业要求、可用期次三大约束，并避免同学生被分到多个单位。
- **目标角色**: 教学秘书、教务干事、辅导员、实习带队老师、院系实习管理专员
- **触发时机**: 每学期实习动员后收集完志愿；单位容量/期次更新后重新分配；对已有分配方案做冲突体检
- **触发语句示例**: "帮我把这批学生的实习单位和期次排一下"、"根据志愿和学生人数分配实习单位"、"检查一下实习分配表有没有超容量"、"这学期实习分单位，按志愿优先来"

## 输入

JSON（支持中英文字段别名，详见 README 输入规范一节）：

```jsonc
{
  "students": [                    // 学生名单（别名：学生/名单/实习生）
    {"name": "李明", "class": "计科2301", "major": "计算机",
     "options": ["云智科技", "星云软件"], "windows": ["w1", "w2"]}
  ],
  "units": [                       // 实习单位（别名：单位/企业/实习单位）
    {"name": "云智科技", "capacity": 20, "majors": ["计算机"], "windows": ["w1"]}
  ],
  "windows": [                     // 期次（别名：期次/批次）
    {"id": "w1", "label": "第1-4周"}, {"id": "w2", "label": "第5-8周"}
  ],
  "assignments": [                 // 已有分配（可选，先占用容量）
    {"student": "李明", "unit": "云智科技", "window": "w1"}
  ],
  "rules": {"major_strict": false, "fallback_any": false, "default_capacity": 10}
}
```

- 输入依赖：仅 JSON（文件 / stdin）；零第三方库，离线可运行；无网络请求。

## 处理逻辑

1. 结构校验与中英文别名归一化（学生/单位/期次/已分配/规则），容量支持 `12` / `"12"` / `"12人"` 宽容解析
2. 负载初始化：已有 `assignments` 先占用「单位×期次」容量；单位开放期次 = 显式列表 > 全局期次 > 单桶（空期次）
3. 确定性贪心：学生按「志愿数量少优先 > 姓名字典序」排序逐个分配，约束依次校验：
   - 志愿顺序（一志愿 > 二志愿 > …，志愿单位不存在则跳过）
   - 容量硬约束（该学生在「单位×期次」内占用 1 个名额，满员即缺口）
   - 专业匹配（`major_strict=true` 时硬校验；单位无要求或学生未填专业视为匹配）
   - 期次交集（学生可用期次与单位开放期次必须相交）
   - 可选自动调剂（`fallback_any=true` 时，志愿全满的学生可调剂到有空余的其他单位，标记"调剂"）
4. 缺口显式告警：未分配学生进 `issues[]`，归因五类——无志愿 / 志愿单位不存在 / 专业不符 / 时段无交集 / 志愿全满，每条附处置建议，绝不静默丢弃
5. 输出 Markdown 报告或 JSON；利用率统计含「已分配/容量/利用率」；`--out` 仅显式指定时才写文件（默认只读预览）
6. **检查模式**（`--check`）：不重新分配，仅对已有 `assignments` 做冲突体检：单位×期次超额、引用未知单位、引用未知期次、同一学生分属多个单位

## 输出

- **Markdown**（默认）：`一、需人工处理（未分配缺口） → 二、分配方案（学生|班级|专业|单位|期次|志愿命中） → 三、单位×期次利用率 → 四、统计汇总（分配率 + 一志愿命中率）`
- **检查模式**：`# 已有实习分配体检报告`，逐条列出问题类型与处置提示；无问题则"检查通过"
- **JSON**（`--json`）：`summary{total_students,assigned,unassigned} / placements[] / issues[] / utilization[] / rules`

## 用法

```bash
python3 scripts/internship_allocator.py input.json              # Markdown 分配方案
python3 scripts/internship_allocator.py input.json --json        # JSON 结果
cat input.json | python3 scripts/internship_allocator.py --json # stdin 输入
python3 scripts/internship_allocator.py input.json --out plan.md # 显式写盘（已存在需 --force）
python3 scripts/internship_allocator.py plan.json --check        # 体检已有分配
# 自测：bash scripts/run_selftest.sh （29 用例，要求 29/29 通过）
```

### 退出码

| 码 | 含义 |
|---|---|
| 0 | 全部学生已分配（check 模式：未发现冲突） |
| 1 | 存在需人工处理项（未分配缺口 / 体检发现问题） |
| 2 | 输入/IO 错误（坏 JSON、缺字段、文件不存在、--out 已存在未加 --force） |

## 已知限制

- 贪心解非全局最优（志愿数量少优先 + 字典序确定性排序）；高满意度需求可人工微调后复跑
- 不接入校友邦/实习管理系统等真实平台，数据均为 JSON 输入；同单位多地、跨城市通勤等约束未建模
- 单位容量按「期次」维度计（每期容量），不区分不同岗位；学生仅分配一家单位，不做多岗位并行

## 安全说明

- 用户可控文本（姓名/单位/期次）在输出时统一 HTML 转义 + Markdown 表格转义 + 控制字符清理，防 XSS 与表格注入
- 不访问网络、不执行用户输入中的任何代码；仅解析 JSON 结构
