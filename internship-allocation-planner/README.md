# 学生实习分配规划器（internship-allocation-planner）

面向教育场景「实习组织管理」的轻量工具：把学生按志愿分配到「实习单位 × 期次」，显式揭示缺口与冲突原因，输出单位×期次利用率，供教学秘书/辅导员做分配决策与人工协调。

- **零依赖**：纯 Python 标准库，离线可跑，无网络请求
- **确定性**：同一输入必然产生同一输出（「志愿数量少优先 > 姓名字典序」）
- **防注入**：所有用户可控文本输出时统一转义；默认只读，写盘需显式指定

## 输入规范

顶层 JSON 对象，各字段支持中英文别名（按序取第一个非空值）：

| 字段 | 英文别名 | 中文别名 | 说明 |
|---|---|---|---|
| students | students | 学生 / 名单 / 实习生 | 学生数组 |
| units | units | 单位 / 企业 / 实习单位 | 单位数组 |
| windows | windows | 期次 / 批次 | 期次字典（可选） |
| assignments | assignments | 已分配 / 分配结果 | 已有分配（可选，先占用容量） |
| rules | rules | 规则 | 规则对象（可选） |

### 学生（students[]）

| 字段 | 别名 | 必填 | 说明 |
|---|---|---|---|
| name | 姓名 / 学生姓名 | 是 | 学生姓名 |
| class | 班级 | 否 | 班级，仅展示 |
| major | 专业 | 否 | 专业，用于专业匹配 |
| options | 志愿 / 志愿单位 / 意向单位 / choice | 否 | 志愿单位列表，按优先级排序（一志愿在前） |
| windows | 可用期次 / 可实习期次 / available | 否 | 学生可在哪些期次实习 |

### 单位（units[]）

| 字段 | 别名 | 必填 | 说明 |
|---|---|---|---|
| name | 名称 / 单位名 / 企业名 | 是 | 单位名称 |
| industry | 行业 / 领域 | 否 | 行业，仅展示 |
| majors | 专业 / 专业要求 | 否 | 专业要求，与 major_strict 配合 |
| capacity | 容量 / 每期容量 / 可接收人数 | 否 | **每期**容量；缺省取规则 default_capacity（默认 10）；支持 "12" / "12人" |
| windows | 开放期次 / 可接期次 / 期次 | 否 | 开放期次；缺省 = 全局期次；无期次定义 = 单桶 |

### 期次（windows[]）

| 字段 | 别名 | 必填 | 说明 |
|---|---|---|---|
| id | 编号 | 是 | 期次标识（如 w1），分配结果中直接引用 |
| label | 名称 / 说明 | 否 | 展示名，缺省用 id |
| start / end | 开始 / 结束 | 否 | 日期说明（仅展示，不参与计算） |

### 规则（rules）

| 字段 | 别名 | 默认 | 说明 |
|---|---|---|---|
| major_strict | 专业严格匹配 | false | true 时专业不匹配按硬约束跳过 |
| fallback_any | 自动调剂 | false | true 时志愿全满的学生可调剂到任何有空位的单位（标记"调剂"） |
| default_capacity | 默认容量 | 10 | 单位未填容量时的兜底值 |

## 分配算法（确定性贪心）

1. 学生排序：`len(options)` 升序（志愿少的先选，减少拥挤）→ 姓名升序（字典序，保证确定性）
2. 对每个学生：按志愿顺序遍历单位 → 单位内按开放期次遍历（显式列表 > 全局 > 单桶）→ 满足「容量未满 + 专业匹配（strict 时）+ 学生期次可用」即分配，标记志愿命中层次（一志愿/二志愿/…/调剂）
3. 全部一轮后仍未分配的学生，若 `fallback_any=true` 则启用调剂池再试一次
4. 仍未分配的学生进入缺口清单，归因五类并附处置建议：
   - **无志愿** → 未填写志愿单位，请人工安排
   - **志愿单位不存在** → 志愿名单与单位清单名称不一致，请核对
   - **专业不符** → 志愿单位有专业要求且不匹配，可与单位协商放宽
   - **时段无交集** → 学生可用期次与单位开放期次无交集，请协商调整期次
   - **志愿全满** → 志愿单位均无剩余容量，请协商增开班次量或调整志愿

## 检查模式（--check）

不重新分配，只读体检已有 `assignments[]`，发现以下问题逐条列出：

- **单位期次数超额**：某单位×期次已分配人数 > 该期容量
- **未知单位**：分配中引用不在单位清单中的单位
- **未知期次**：分配中引用了单位开放期次之外的期次
- **学生分属多单位**：同一学生被分配到多个单位

## 输出与副作用

- Markdown（默认）或 JSON（--json）；stdout 输出即只读，不写任何文件
- `--out <file>` 显式写盘；目标文件已存在时拒绝覆盖（需加 `--force`）
- 退出码：0=无缺口/无冲突，1=存在需人工处理项，2=输入/IO 错误

## 安全设计

- 用户可控文本（姓名/单位/期次/班级）输出时统一：HTML 转义（`& < > " '`）→ Markdown 表格转义（`|` → `\|`）→ 换行转 `<br>` → 控制字符剔除，防 XSS 与表格注入
- 不访问网络、不执行输入中任何代码；仅解析 JSON 结构
- 默认只读：写盘必须显式 `--out`，覆盖必须 `--force`

## FAQ

**Q: 单位容量是每期还是总数？**
A: 单位容量是「每期容量」：容量 20、开放 2 个期次 = 可接收 40 人次。这与集中实习轮岗场景一致；如需按全期总量，可将单位开放期次设为单个期次。

**Q: 学生没填志愿怎么办？**
A: 会进入缺口清单「无志愿」，提示人工安排，不会被静默丢弃。

**Q: 想先按班级整体优先分配？**
A: 排序策略为志愿数量少优先（默认）。如需别的优先策略，可调整 options 数量或人工微调后复跑；贪心解非全局最优。
