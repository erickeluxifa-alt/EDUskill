# 实验室预约防冲突排程器

## 一句话定位

输入「实验室资源 + 预约申请」，1 秒内输出无冲突预约排程表 + 需人工协调的缺口清单 + 资源利用率统计（零依赖、离线可跑）。

## 场景与目标角色

- **场景**: 实验中心/教务处在新学期实验排课、开放预约、临时加开实验时，批量安排"实验课程 → 实验室 × 时段"，避免同一实验室同时段被重复预约、类型/设备/容量不匹配、教师时间冲突。
- **目标角色**: 实验室管理员、实验员、实验中心干事、院系教学秘书、教务干事
- **触发时机**: 每学期实验排课阶段；每周开放预约收集后；调课/加开实验时
- **触发语句示例**: "帮我把这个月的实验室预约排一下"、"给这两周的实验课分机房"、"检查这些实验室预约有没有冲突"、"按设备要求安排电路实验的实验室"

## 输入

JSON（支持中英文字段别名，详见 README 输入规范一节）：

```jsonc
{
  "resources": [                       // 实验室资源（别名：实验室/资源/rooms/labs）
    {"id": "计算机机房一", "type": "机房", "capacity": 60, "设备": ["示波器"]},
    {"id": "数控加工中心", "type": "数控", "capacity": 15, "equipment": ["三轴数控铣床"],
     "开放日期": ["2026-09-09"]}
  ],
  "bookings": [                        // 已排定占用（可选）
    {"name": "b01", "date": "2026-09-09", "slot": "08:00-10:00",
     "resource": "计算机机房一", "人数": 50, "teacher": "刘丽"}
  ],
  "requests": [                        // 预约申请（别名：预约申请/预约/applications）
    {"id": "r01", "实验课程": "大学物理实验", "班级": "物理2301", "人数": 40,
     "教师": "王明", "日期": "2026-09-09", "时段": "14:00-16:00", "资源类型": "物理"},
    {"id": "r02", "course": "数控实验", "students": 40, "teacher": "赵强",
     "date": "2026-09-09", "res_type": "数控", "split": true}
  ],
  "rules": {"split": true, "teacher_conflict": true, "capacity_strict": true}
}
```

- 输入依赖：仅 JSON（文件 / stdin）；零第三方库，离线可运行；无网络请求。

## 处理逻辑

1. 结构校验与中英文别名归一化（资源/申请/已排定/规则），日期支持 `2026-09-09` / `2026/9/9` / `2026年9月9日`
2. 负载初始化：已排定 bookings 按「日期+时段+资源」占用座位与教师日程
3. 确定性贪心：申请按优先级(高→低)→人数(大→小)→序 排序；逐个申请在偏好时段内寻找可用资源，约束依次校验：
   - 容量硬约束（默认；人数 > 剩余容量即缺口）
   - 类型匹配（申请指定 `res_type` 时仅用同类型资源）
   - 设备匹配（申请设备 ⊆ 资源设备）
   - 资源独占（同资源同日期同时段仅一单，`max_per_resource_slot` 可调）
   - 教师互斥（同教师同日同时段不可两处，可关闭）
   - 单资源同槽位内按「剩余容量大优先」分片消化；整单装不下且允许拆分时跨槽位续排
4. 缺口显式告警：任何未排完的人数进 `issues[]`（含缺口人数与处置建议），绝不静默丢弃
5. 输出 Markdown 报告或 JSON；利用率统计含已排定占用；`--out` 仅显式指定时才写文件（默认只读预览）

## 输出

- **Markdown**（默认）：`一、需人工处理（缺口/冲突） → 二、预约排程表（日期|时段|资源|类型|课程|班级|人数|教师） → 三、资源利用率`
- **JSON**（`--json` / `--out`）：`summary{total_requests,resolved,chunks,issues} / issues[] / plan[] / utilization[]`

## 用法

```bash
python3 scripts/lab_reservation_scheduler.py input.json          # Markdown 报告
python3 scripts/lab_reservation_scheduler.py input.json --json   # JSON 结果
cat input.json | python3 scripts/lab_reservation_scheduler.py --json
python3 scripts/lab_reservation_scheduler.py input.json --out plan.json   # 显式写盘
# 自测：bash scripts/run_selftest.sh （29 用例，要求 29/29 通过）
```

### 退出码

| 码 | 含义 |
|---|---|
| 0 | 所有申请均解决 |
| 1 | 存在需人工处理项（缺口/冲突） |
| 2 | 输入/IO 错误（坏 JSON、缺字段、文件不存在） |

## 已知限制

- 贪心解非全局最优（高性价比调度可人工微调后复跑）；暂不含可视化甘特图与 Excel/CSV 导出
- 不接入真实实验室管理系统/教务系统，数据均为 JSON 输入；多校区/跨楼宇距离要求未建模
- 时段为离散槽位（默认 5 段，可自定义），不支持分钟级自由时段

## 安全说明

- 用户可控文本（课程/班级/教师名）在输出时统一 HTML 转义 + Markdown 表格转义，防 XSS 与表格注入
- 不访问网络、不执行用户输入中的任何代码；仅解析 JSON 结构
