# 效果自评 — 实验室预约防冲突排程器 v1.0.0（2026-08-20）

## 能力准确性：94/100
- 六维约束（容量/类型/设备/资源独占/教师互斥/开放日期）在 29 条用例中全部按预期生效，含组合场景（中英别名+日期形态+已排定占用+跨槽拆分+缺口揭示）逐字段核对通过；
- 拆分语义：容量内同槽跨资源拆分、超容量跨槽续排、关闭拆分即缺口，三种分支行为明确；优先级排序确定性可复现；
- 扣分项：贪心算法为局部最优，未做全局优化对比；`to_slot_name` 对部分字形（如 `08:10` 而非 `08:00`）容忍度有限（会回退到全时段扫描而非报错）。

## 可用性：90/100

- 零依赖 Python3 标准库 ~480 行 CLI，离线可跑；中文别名和三种日期形态有效降低使用门槛；
- 默认只读预览 + `--out` 显式写盘，满足"先预览确认再落盘"的交互要求；
- 扣分项：无 GUI/网页入口，输出为 Markdown/JSON 文本，需要用户自行贴表或接下游工具。

## 稳定性：100/100

- 坏 JSON、空列表、0 人/负人、超长人数（2000）、非对象条目、XSS 文本等 17 类异常与非输入全部不崩溃、不静默丢单（缺口必提示）；退出码语义 0/1/2 稳定。

## 行业适配度：88/100

- 场景真实高频：高校实验排课、开放实验室预约冲突（公开资料印证：*智慧实验室系统产品解决方案* 明确列出"纸质登记、冲突多 → 线上预约、策略自动排冲突，利用率↑20%"作为行业痛点，链接见日报"公开资料来源"）；
- 资源类型/设备清单/开放日期/教师互斥等字段契合实验室中心实际台账；
- 扣分项：未建模多校区/设备共享数量（如 30 台设备中的可用台数）、分钟级预约、与校园一卡通/实验室管理系统的对接（原型阶段以 JSON 为准）。

## 未覆盖风险

1. 未接入真实实验室管理系统/教务系统，数据均为模拟 JSON；真实字段结构与现有 schema 可能不一致，需适配层；
2. 无甘特图/Excel 导出，排程结果需人工二次加工交付教务处；
3. 优先级/拆分策略为固定规则，未支持"同班同时段不拆"等复杂业务偏好（可通过 `split:false` 规避一部分）；
4. 需求不可解决时的缺口建议只给出方向性提示，最终人工决策。

## 结论

原型价值得到验证：四件套约束 + 缺口揭示 + 利用率统计形成了"输入 JSON → 可核对的排程草案"闭环，延续 08-17 排课检测（检测→生成）与 08-19 考场编排（生成+缺口）的可复用模式，可作为实验室/机房/收费预约的"排程内核"进一步迭代（优先：Excel 导出、甘特图、批次批量导入、真实系统适配层）。
